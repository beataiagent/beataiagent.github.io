The open-world problem

New task, old harness

Agents keep meeting tasks their harness was not designed for

Retrain the model

  • Needs data and GPUs
  • Slow to iterate
  • Not possible for API models

Hand-tune the harness

  • Engineer edits prompts and skills
  • Does not scale to every task
  • Lessons stay in people's heads

Harness²

  • Agent edits its own harness, per task
  • Keeps lessons in a library
  • Model weights stay frozen
ปัญหา: ในโลกจริง agent เจองานที่ harness ไม่ได้ออกแบบมารองรับตลอด • (คลิก) ทางแรก retrain โมเดล ต้องมีข้อมูลและ GPU ช้า และทำไม่ได้กับโมเดลผ่าน API • (คลิก) ทางที่สอง คนมานั่งแก้ prompt และ skill เอง ไม่ scale • (คลิก) Harness² ให้ agent แก้ harness ของตัวเองทีละงาน และเก็บบทเรียนไว้ใน library โดยโมเดลไม่เปลี่ยน
02

How Harness²
works

Recursion on two levels:
the task, and the harnessing itself

ช่วงที่ 2 • ทำไมชื่อ Harness ยกกำลังสอง เพราะมี recursion 2 ชั้น
Why "squared"

Two levels of recursion

Level 1 · Task

Refine the harness for this task

  • Propose edits, Probe them on the same task, Compose a better harness
  • Learns from behavior contrasts between runs
  • No ground-truth score or rubric
Level 2 · Harnessing

Improve how future tasks are refined

  • A persistent improvement library
  • Stores adopted harnesses and lessons backed by evidence
  • One library per domain
(คลิก 1) ชั้นที่ 1 ระดับงาน: เสนอการแก้ (Propose) ลองรันดูกับงานเดิม (Probe) แล้วรวมส่วนที่ได้ผลเป็น harness ใหม่ (Compose) สำคัญคือไม่มีการดูคะแนนหรือ rubric ตัดสินจากพฤติกรรมที่เห็นต่างกันระหว่างการรันเท่านั้น • (คลิก 2) ชั้นที่ 2 ระดับ harnessing: หลังจบงาน เก็บ harness ที่ใช้ได้และบทเรียนที่มีหลักฐานลง improvement library เพื่อให้งานถัดไปปรับได้ดีขึ้น library แยกตาม domain
Level 1 · one task

Propose · Probe · Compose

Reference run

Start from the base harness H₀

Propose

Harness editor writes general and domain-specific edits

Probe

Run each candidate on the same task

Compose

Composer merges what worked into one harness

Reflect

Deliver, then write lessons to the library

The next task starts again at H₀. Reuse happens through the library, not by carrying the harness forward.

Key ruleNo step sees a score or rubric. Every decision rests on observed behavior.
ลูปต่อ 1 งาน • (คลิก 1) รันอ้างอิงก่อนด้วย harness ตั้งต้น H₀ • (คลิก 2) Propose: harness editor เสนอการแก้ 2 แบบ คือแบบทั่วไป (invariant) และแบบเฉพาะ domain • (คลิก 3) Probe: ลองรันแต่ละตัวเลือกกับงานเดิม • (คลิก 4) Compose: composer เอาส่วนที่ได้ผลมารวมเป็น harness เดียว • (คลิก 5) Reflect: ส่งงาน แล้ว experience reflector เขียนบทเรียนลง library • (คลิก 6) งานถัดไปเริ่มจาก H₀ ใหม่ ไม่ได้ส่ง harness ต่อ แต่ใช้ความรู้ผ่าน library • (คลิก 7) กฎสำคัญ: ไม่มีขั้นไหนเห็นคะแนน ตัดสินจากพฤติกรรมล้วน ๆ
Two knobs: budget k and mode

Parallel or sequential?

--mode parallel
  • Propose and probe k general + k domain candidates at once
  • Make k compositions from the shared evidence
  • The default mode
--mode sequential
  • k Propose–Probe–Compose steps in a row
  • Each step carries the refined harness and evidence forward
TipAt k = 1 the two modes are the same. Start there: higher k means more model calls.
มี 2 ปุ่มให้ปรับ: งบ k กับโหมด • (คลิก 1) parallel: เสนอและทดลองตัวเลือกทั่วไป k ตัวและเฉพาะ domain k ตัวพร้อมกัน แล้วรวมได้ k แบบ เป็นค่า default • (คลิก 2) sequential: ทำ Propose–Probe–Compose ต่อกัน k รอบ แต่ละรอบต่อยอดจากรอบก่อน • (คลิก 3) ที่ k=1 สองโหมดเหมือนกัน แนะนำเริ่มที่ k=1 เพราะ k มากขึ้นคือเรียกโมเดลมากขึ้น

Step 4 · runs/lab/ · runs/jb/ · runs/wb/<subset>/

The refined harness on disk

Always on ≤ 24,000 chars

  • systemprompt.md role
  • guardrails.md rules
  • LongTermMEMORY.md memory
  • tool_descriptions/tool_guidance.md tools

On demand

  • sub_agents/<name>/AGENT.md subagent
  • skills/<name>/SKILL.md skill
  • scripts/<name>.py script
  • plugin/<name>.ts plugin
ReadableThe result is plain files you can review, diff and reuse, not new model weights.
ผลที่ได้คือ harness ในรูปไฟล์ธรรมดา • ส่วนที่โหลดทุกครั้ง: system prompt, guardrails, memory, tool guidance รวมกันไม่เกิน 24,000 ตัวอักษรใน OpenCode • (คลิก) ส่วนที่โหลดเมื่อต้องใช้: subagent, skill, script และ plugin • (คลิก) ข้อดีคือเปิดอ่าน diff และเอาไปใช้ต่อได้ ไม่ใช่ weight ที่อ่านไม่ออก • ตัวอย่างใน setup guide: งาน HR ใน JobBench ได้ harness ที่มี role prompt, guardrails 5 ข้อ, skill 13.9 KB และ script ตรวจงาน
Before the first real run

Cost & safety

Cost grows with k

Per task, per mode: 4 × k executor runs and 3 × k improver sessions, plus judge calls.

Full LAB at k=5: ~22,860 runs

Block the answers

After setup, block huggingface.co and github.com at the network layer. JobBench rubrics are public.

Start small

There is no spend cap. Set a budget alert, use --max-tasks 1, and run only offline, repeatable tasks.

Note"This is not an officially supported Google product." Research code, v0.1.0.
ก่อนรันจริง 3 เรื่อง • (คลิก 1) ค่าใช้จ่ายโตตาม k: ต่องานต่อโหมดประมาณ 4×k ครั้งที่รัน executor และ 3×k session ของ improver ยังไม่รวม judge ถ้ารัน LAB ทั้งชุด 1,143 งานที่ k=5 จะประมาณ 22,860 รอบ • (คลิก 2) agent เข้าเน็ตได้ และ rubric ของ JobBench เปิดเผยบน Hugging Face เคยมีกรณี Codex ไปโหลด rubric เอง ต้องบล็อกที่ระดับ network • (คลิก 3) repo ยังไม่มีเพดานค่าใช้จ่าย ตั้ง budget alert ก่อน และใช้กับงานที่ไม่มีผลข้างเคียง เช่น ไม่ส่งอีเมล ไม่แตะ DB จริง เพราะ k>1 คือรันงานเดียวกันหลายรอบ • (คลิก 4) เป็น research code ไม่ใช่ product ที่ Google support
