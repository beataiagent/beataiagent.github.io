Picking the Cloud Run resource

Service or Instance?

Cloud Run Service
  • Auto-scales with requests
  • Many copies, all the same
  • Fine for Hermes in Gateway mode only
Cloud Run Instance
  • Long-lived and runs on its own
  • One addressable environment
  • Runs up to 7 days, then restarts by itself
  • Fits a stateful agent with background work
⚠ Watch outNever point two Hermes gateways at the same data folder. Sessions and memory can get corrupted.
(คลิก 1) Cloud Run Service ขยายตามจำนวน request มีหลายตัวที่เหมือนกัน ใช้กับ Hermes ได้ถ้ารันแค่ Gateway mode • (คลิก 2) แต่ Hermes scan skill ตอนบูตและทำงานเบื้องหลัง เป็น agent ที่มี state จึงเหมาะกับ Cloud Run Instance: อยู่ได้นาน มีตัวเดียวเรียกถึงได้ตรง ๆ รันต่อเนื่องได้ถึง 7 วันแล้ว restart ให้เอง • (คลิก 3) ข้อควรระวังจาก docs ของ Hermes: อย่าให้ gateway สองตัวใช้โฟลเดอร์ข้อมูลเดียวกัน ข้อมูลจะเสีย นี่คืออีกเหตุผลที่ไม่ควร auto-scale

Gemini through Vertex AI · no API key, the service account is the credential

(คลิก 1) สร้าง bucket ใน region เดียวกัน และให้ hermes-sa เป็น objectAdmin เพื่อ mount และเขียนไฟล์ได้ bucket นี้จะกลายเป็นโฟลเดอร์ /opt/data ใน container • (คลิก 2) config.yaml: ใช้ Gemini ผ่าน provider vertex เปิด dashboard และตั้ง journal_mode ของฐานข้อมูลเป็น delete ไม่ใช้ WAL ซึ่งจะอธิบายในสไลด์ถัดไป • (คลิก 3) ไม่ต้องมี API key เพราะใช้สิทธิ์ของ service account
The tricky part

Cloud Storage is not a normal disk

Cloud Storage FUSE is built for objects and is not fully POSIX compliant

No byte-range locksSQLite in WAL mode and busy caches need file locks
RiskCorrupted state.db and blocked I/O
FixDo the busy work in local /tmp, copy back to the bucket
Local
SQLite, locks, uv & XDG caches
TRUNCATE mode
One database file, easy to copy
Autosave
Changed files go back every 5 s
ส่วนที่ยากที่สุด • Cloud Storage FUSE ทำให้ bucket ดูเหมือนโฟลเดอร์ แต่ไม่ใช่ disk จริง ไม่รองรับ POSIX เต็มรูปแบบ • (คลิก) ไม่มี byte-range file lock ซึ่ง SQLite แบบ WAL และ cache ต้องใช้ • (คลิก) ผลคือ state.db เสียและ I/O ค้าง • (คลิก) ทางแก้: ทำงานที่เขียนบ่อยใน /tmp ของ container แล้ว copy กลับขึ้น bucket • (คลิก) สรุป 3 อย่าง: SQLite และ cache อยู่ local / ตั้ง SQLite เป็น TRUNCATE ให้มีไฟล์เดียว copy ง่าย / autosave ไฟล์ที่เปลี่ยนกลับขึ้น bucket ทุก 5 วินาที
Step 5 · run_hermes.py

A small Python supervisor

  1. 1Make local folders in /tmp
  2. 2Restore config.yaml, .env, state.db from the bucket
  3. 3Set SQLite to TRUNCATE
  4. 4Point HOME, HERMES_HOME, caches at /tmp
  5. 5Start the autosave thread
  6. 6Launch Gateway + Dashboard on :8080

def sync_to_gcs_loop():
  files_to_sync = ["state.db", "config.yaml", ".env"]
  ...
  while True:
    time.sleep(5)
    for f in files_to_sync:
      src_path = os.path.join(hermes_dir, f)
      mtime = os.path.getmtime(src_path)
      if mtime > last_mtimes.get(f, 0):
        dst_path = os.path.join("/opt/data/.hermes", f)
        shutil.copy2(src_path, dst_path)
        last_mtimes[f] = mtime

threading.Thread(target=sync_to_gcs_loop, daemon=True).start()
✦ Full scriptCopy run_hermes.py from the codelab (step 5.3). It is about 150 lines with comments.
run_hermes.py ทำ 6 อย่างตามลำดับ: (1) สร้างโฟลเดอร์ใน /tmp (2) copy config, .env และ state.db จาก bucket มาไว้ local ทำให้แชตเก่ากลับมา (3) ตั้ง SQLite เป็น TRUNCATE (4) ตั้ง env ให้ Hermes ใช้ /tmp แทน bucket เช่น HOME, HERMES_HOME, UV_CACHE_DIR (5) เปิด thread autosave ดูโค้ดด้านขวา: ทุก 5 วินาทีเช็กเวลาแก้ไขไฟล์ ถ้าเปลี่ยนก็ copy กลับไปที่ /opt/data/.hermes ซึ่งคือ bucket (6) เปิด Gateway และ Dashboard เป็น subprocess ส่ง log ออก stdout ให้ Cloud Run เก็บ • สคริปต์เต็มก็อปจาก codelab ได้เลย

A startup script, then upload

start_hermes.sh 

#!/bin/sh

export PYTHONUNBUFFERED=1

The scripts live in the bucket, not in the image. Edit a script and redeploy, no rebuild. The official image runs /bin/sh /opt/data/start_hermes.sh.
(คลิก 1) start_hermes.sh สั้นมาก แค่เรียก run_hermes.py • (คลิก 2) อัปโหลด 3 ไฟล์ขึ้น bucket • (คลิก 3) จุดเด่น: สคริปต์อยู่ใน bucket ไม่ได้อยู่ใน image เราใช้ image ทางการของ Nous Research ตรง ๆ แล้ว override command ให้รันสคริปต์จาก /opt/data แก้สคริปต์แล้ว redeploy ได้เลยโดยไม่ต้อง build image ใหม่

Step 7 · gcloud beta run instances deploy

Deploy with one command


gcloud beta run instances deploy hermes-instance \
  --image nousresearch/hermes-agent:latest \
  --service-account ${SERVICE_ACCOUNT} \
  --command "/bin/sh" \
  --args "/opt/data/start_hermes.sh" \
  --port 8080 \
  --cpu 2 \
  --memory 4Gi \
  --ingress all \
  --no-invoker-iam-check \
  --add-volume name=hermes-storage,mount-path=/opt/data,\
type=cloud-storage,bucket=$BUCKET_NAME,\
mount-options="uid=2000;gid=2000;file-mode=0777;dir-mode=0777;implicit-dirs" \
  --set-secrets "HERMES_DASHBOARD_BASIC_AUTH_PASSWORD=hermes-dashboard-password:latest" \
  --set-env-vars "PYTHONUNBUFFERED=1,VERTEX_PROJECT_ID=$PROJECT_ID,\
VERTEX_LOCATION=global,HERMES_DASHBOARD_BASIC_AUTH_USERNAME=admin,\
HERMES_ALLOW_ROOT_GATEWAY=1,HERMES_WORKSPACE=/opt/data/workspace,\
HERMES_WRITE_SAFE_ROOT=/opt/data" \
  --region $REGION \
  --project $PROJECT_ID
--command / --argsRun our script from the bucket
--add-volumeMount the bucket at /opt/data
--set-secretsPassword from Secret Manager
--no-invoker-iam-checkPublic URL, protected by the dashboard login
คำสั่งเดียว: gcloud beta run instances deploy • ใช้ image ทางการ แนบ service account hermes-sa 2 CPU 4 GiB • (คลิก 1) --command กับ --args ให้รัน start_hermes.sh จาก bucket • (คลิก 2) --add-volume mount bucket เป็น /opt/data ด้วย Cloud Storage FUSE ตั้ง uid/gid และ permission ให้เขียนได้ และ implicit-dirs ให้เห็นโฟลเดอร์ • (คลิก 3) --set-secrets ใส่รหัสผ่านจาก Secret Manager เป็น env • (คลิก 4) --no-invoker-iam-check ให้เปิด URL ได้โดยไม่ต้องมี IAM ความปลอดภัยมาจาก login ของ dashboard ถ้าใช้จริงควรคิดเรื่องจำกัดการเข้าถึงเพิ่ม • ก่อนรันเช็กว่า export ตัวแปร PROJECT_ID, REGION, BUCKET_NAME, SERVICE_ACCOUNT ครบ

Step 10 · Avoid charges

Clean up


gcloud beta run instances delete hermes-instance --region ${REGION} --quiet
gcloud secrets delete hermes-dashboard-password --quiet
gcloud storage rm -r gs://${BUCKET_NAME}
gcloud iam service-accounts delete ${SERVICE_ACCOUNT} --quiet

An instance keeps running until you delete it

⚠ Carefulgcloud storage rm -r deletes the agent's chats, config and workspace. Back up first if you want to keep them.
ลบ 4 อย่างเพื่อไม่ให้เสียเงิน: instance, secret, bucket และ service account • instance รันอยู่จนกว่าเราจะลบ • (คลิก) ระวัง: ลบ bucket คือลบแชต config และ workspace ทั้งหมด ถ้าอยากเก็บไว้ให้ backup ก่อน
