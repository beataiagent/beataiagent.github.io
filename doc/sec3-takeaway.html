2. The 6-pillar architecture summary grid

3.1 Single-agent params
description vs. instruction
  • description: Read by parent routers to delegate tasks.
  • instruction: Steers internal LLM brain + {state}.
  • output_key: Saves reply to session.state.
3.2 Workflow patterns
Sequential, Parallel, and Loop
  • Deterministic orchestrators use zero LLM calls for routing.
  • ParallelAgent: Unique output_key per branch.
  • LoopAgent: Exit via escalate=True.
3.3 MCP and custom tools
MCP Toolbox for Databases
  • tools.yaml: sources, tools, toolsets for pooled DBs & hot-reload.
  • AgentTool: Isolates built-in Search/Code tools.
3.4 Grounding and caching
Search vs. RAG vs. Cache
  • Agent Search: Turnkey SaaS connectors + ACLs.
  • RAG Engine: Custom chunking + reranking.
  • Context Caching: Static 32k+ token reuse.
3.5 State and Memory Bank
4 prefixes and Artifacts
  • Scopes: temp: (1 turn), no prefix (1 session), user: (user), app: (global).
  • Memory Bank: Long-term facts.
  • Artifacts: Versioned PDFs/blobs.
3.6 A2A protocol
Agent Cards and Task states
  • Discovery: /.well-known/agent.json.
  • Transport: SSE (live) vs. Push Webhooks (hours).
  • Paused state: input-required (reuse taskId).

3. Master “if you see X, pick Y” decision matrix (Section 3)

Architectural requirement or scenario Recommended Google Cloud / ADK solution Anti-pattern to avoid
Fix a parent coordinator that routes tasks to the wrong specialist sub-agent Update the child agents’ description parameter so capabilities are distinct and mutually exclusive. Rewriting the child agent’s internal instruction or changing output_key.
Run 3 independent API/database checks concurrently and synthesize the results Wrap a ParallelAgent (with 3 unique output_key names) and a synthesizer LlmAgent inside a SequentialAgent. Running all 3 checks sequentially or sharing one output_key across parallel branches.
Connect multiple agents to AlloyDB, Cloud SQL, Spanner, or BigQuery with pooling MCP Toolbox for Databases configured via declarative tools.yaml (sources, tools, toolsets). Letting the LLM execute raw SQL strings over unpooled database connections in Python.
Ground an agent on SharePoint/Drive/Jira while enforcing document-level user ACLs Agent Search on the Gemini Enterprise Agent Platform with identity-aware ACL filtering. Gemini Context Caching or a custom RAG corpus without ACL metadata.
Cut latency and token costs when querying the exact same 400-page PDF on every turn Gemini Context Caching (CachedContent / ContextCacheConfig) with an appropriate TTL. Re-sending the raw 400-page PDF in every prompt or chunking it when full-document reasoning is required.
Store a 20-MB customer PDF or generated chart image without bloating session.state ArtifactService (GcsArtifactService) using save_artifact() and load_artifact(). Base64-encoding the PDF into session.state or storing binary blobs in Memory Bank.
Delegate a multi-turn, stateful goal to an external partner’s opaque agent Agent2Agent (A2A) protocol (RemoteA2aAgent, Agent Card, and input-required / Push Webhooks). Exposing the stateful partner agent as a stateless MCP database tool.

Golden rules for Section 3

  1. Single-agent & workflows: Parent routing reads description; split tools + output_schema across two sequential agents; give every ParallelAgent branch a unique output_key; exit LoopAgent via EventActions(escalate=True); wrap built-in tools in AgentTool.
  2. Data, grounding & state: Use MCP Toolbox (tools.yaml) for databases, Agent Search for SaaS ACLs, RAG Engine for custom chunking/reranking, Context Caching for static 32k+ token manuals, Memory Bank for cross-session facts, and GcsArtifactService for binary files.
  3. Peer interoperability (A2A): Publish /.well-known/agent.json via to_a2a(), consume via RemoteA2aAgent, use SSE for live streaming, Push Webhooks for multi-hour tasks, and reuse taskId on input-required!
