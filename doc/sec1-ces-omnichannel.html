1.3 CX Agent Studio (CES): Playbooks, state-machine Pages, and composite voice

The Rosku Bank contact-center challenge: state-machine rules and voice pacing!

Rosku Bank is building an omnichannel voice and web agent in CX Agent Studio (CES) and hits three design challenges:

  1. Strict compliance steps: When a caller reports a stolen debit card, compliance requires collecting Card last 4 digits → Date of birth → 4-digit PIN in a strict, unskippable sequence and reading a verbatim legal notice—which an open-ended LLM prompt occasionally skips or paraphrases!
  2. Robotic voice and alphanumeric errors: On the phone channel, callers interrupt the bot mid-sentence, and the bot needs natural pacing, clear alphanumeric pronunciation, and touch-tone keypad (DTMF) capture in noisy train stations.
  3. Blind call transfers: When a caller fails PIN verification twice (no-match) or gets angry, the call transfers blindly to a human rep—forcing the caller to repeat everything!
Module 1.3 in a nutshell
  • Hybrid orchestration: Use Generative Playbooks (steered by few-shot Exemplars) for open-ended conversation and tool calls, and transition to Deterministic Flows for strict step-by-step KYC/PCI verification and word-for-word legal disclosures.
  • How Flows are built: A Flow contains state-machine Pages. Each Page collects Form Parameters (Slots), evaluates Intents and Condition Transition Routes to move to the next Page, and uses Event Handlers (no-match, no-input, webhook errors) to handle fallbacks.
  • Modern composite voice architecture: CX Agent Studio uses a 3-part composite voice model (Listener, Thinking, and Speaker models) steered by natural-language Speaking style descriptions and inline angle-bracket tags (like <pause>) alongside barge-in and redacted DTMF keypad input.

1. Key definitions and how Playbooks, Flows, Pages, Intents, and Event Handlers align

1. Generative Playbook and Exemplars
Goal-driven LLM + few-shot examples
  • What it is: An LLM-driven conversational unit defined by natural-language goals, instructions, and OpenAPI/data store tools.
  • Why you need it: Handles flexible, multi-intent customer questions. Adding Exemplars (sample conversations) teaches the Playbook the exact order to call tools without writing Python code.
2. Deterministic Flow and Pages
Flow → Pages → Form slots
  • What it is: A Flow is a strict state machine made of Pages. Each Page represents one step (e.g., Verify_KYC_Page) and holds required Form Parameters (Slots).
  • Why you need it: Guarantees that mandatory fields (like card number, birth date, and PIN) are collected in an exact, unskippable sequence.
3. Intents and Transition Routes
Intent match + boolean condition
  • What it is: An Intent recognizes what the user wants. A Transition Route checks if an Intent matched or a condition is true (e.g., $page.params.status = ‘FINAL’) to move to the next Page.
  • Why you need it: Controls normal step-by-step movement across Pages, Flows, and Playbooks.
4. Event Handlers (fallbacks)
no-match / no-input / webhook error
  • What it is: Error catchers attached to a Page or Flow for unrecognized speech (sys.no-match-default), caller silence (sys.no-input-default), or API failures.
  • Why you need it: Lets you re-prompt the user up to a fixed limit (e.g., 2 retries) and then escalate cleanly to a human representative.
5. 3-part composite voice model
Listener + Thinking + Speaker
  • What it is: CX Agent Studio’s voice engine combining a Listener model (barge-in/turn-taking), Thinking model, and Speaker model.
  • Why you need it: Lets you steer voice tone, pacing, and digit reading using short Speaking style descriptions and inline tags like <pause> instead of complex XML code.
6. Redacted DTMF and warm handoff
Keypad digits + AI summary transfer
  • What it is: DTMF captures phone keypad digits with log redaction; warm handoff transfers callers to human reps with session params and an AI summary.
  • Why you need it: Protects PCI card numbers in logs and ensures frustrated callers never have to repeat their story to a human agent.
How Playbooks, Flows, Pages, Intents, and Event Handlers are technically arranged:
  • Top level (hybrid orchestration): A Generative Playbook handles open-ended triage and transitions to a Deterministic Flow whenever strict compliance or slot-filling is needed (sharing parameters via the session parameter store).
  • Inside a Flow (the state machine): Flow → contains multiple Pages (states).
  • Inside a Page (3 evaluation pillars): Each active Page evaluates: (1) Form Parameters (Slots) to collect required inputs in order, (2) Transition Routes (triggered by Intents, boolean parameter Conditions, or both) to transition to the next Page/Playbook, and (3) Event Handlers (no-match, no-input, webhook failure) to handle errors and bound retries!

4. Real-world deep dive: state-machine mechanics, Exemplars, and composite voice UX

Architect question Plain-English answer
“How do we stop a Deterministic Flow from re-asking for account_id if the customer already gave it to the Generative Playbook?”
  • Shared session parameter store: Map the Playbook’s extracted parameter to the shared session parameter namespace ($session.params.account_id).
  • When control enters the Flow’s Page, the Page sees that the account_id form parameter is already filled and automatically skips prompting for it!
“What if a Generative Playbook calls generate_payoff_letter before calling check_loan_payoff? How do we fix the tool order without writing Python code?”
  • Add curated Exemplars to the Playbook: In CX Agent Studio, Exemplars act as structured few-shot trajectories.
  • Adding 3–5 Exemplars that demonstrate the Playbook calling check_loan_payoff first and generate_payoff_letter second steers the LLM’s tool-ordering behavior declaratively!
“What is the difference between a Transition Route and an Event Handler on a Page?”
  • Transition Routes evaluate expected user Intents (e.g., Confirm_Cancel_Intent) or boolean Conditions (e.g., all form slots filled: $page.params.status = ‘FINAL’) to move to the next Page.
  • Event Handlers catch unexpected runtime exceptions—like unrecognizable speech (sys.no-match-default), silence (sys.no-input-default), or a webhook 500 error!
“How does CX Agent Studio’s 3-part composite voice model improve upon legacy SSML tags?”
  • Instead of hand-coding verbose XML tags on every line, CX Agent Studio coordinates a Listener model (barge-in/endpointing), Thinking model, and Speaker model.
  • You steer the Speaker model globally with a short Speaking style description (for tone and digit-by-digit alphanumeric clarity) and lightweight inline angle-bracket tags like <pause> (while still supporting SSML <say-as interpret-as=“digits”> when needed)!

Golden rules for Module 1.3

  1. Open-ended goal reasoning = Generative Playbooks (steered declaratively via Exemplars).
  2. Strict slot-filling order, DTMF PINs, and verbatim legal text = Deterministic Flow Pages (using Transition Routes for Intents/Conditions and Event Handlers for no-match/no-input fallbacks).
  3. Natural voice pacing and interruptions = 3-part composite voice model (Listener + Thinking + Speaker with Speaking style descriptions, inline <pause> tags, barge-in, and redacted DTMF).
  4. Frustrated caller or repeated fallbacks = warm live-agent handoff with session params + AI transcript summary!
