2. The 4-pillar architecture summary grid

4.1 Trajectory and rubrics
EXACT, IN_ORDER, ANY_ORDER
  • EXACT: Strict 1-to-1 sequence.
  • IN_ORDER: Extra helper tools allowed.
  • ANY_ORDER: Parallel fan-out.
  • Rubrics: RubricBasedCriterion, PointwiseMetric, PairwiseMetric.
4.2 Production runtimes
Agent Runtime vs. Run vs. GKE
  • Agent Runtime: Zero-ops AdkApp + native Sessions/Memory.
  • Cloud Run: Custom Docker + scale-to-zero (+ external DB).
  • GKE Sandbox: gVisor/microVMs for untrusted code.
4.3 Starter Pack and CI/CD
Automated release gates
  • Agent Starter Pack: Scaffolds Terraform IaC, CI/CD, RAG sync, and BigQuery sinks.
  • Gates & rollouts: AgentEvaluator + session-pinned canary + mocked shadow tools.
4.4 Trace and optimization
OpenTelemetry and flywheel
  • Cloud Trace: Nested spans + W3C traceparent.
  • BigQuery sink: 5% async autorater + golden harvest.
  • Resilience: Provisioned Throughput + backoff with jitter.

3. Deep-dive rubric and evaluation syntax cheat sheet

Review the exact rubric class names, criterion keys, and template parameters across ADK and the Platform Evaluation SDK:

Rubric or evaluation identifier Exact class and parameter syntax What it grades and how it works Primary selection trigger
rubric_based_final_response_quality_v1 (ADK criterion key) RubricBasedCriterion(threshold=0.8, judge_model_options=JudgeModelOptions(...), rubrics=[Rubric(rubric_id="...", rubric_content=RubricContent(text_property="..."))]) Uses an LLM autorater to grade the agent’s final response against custom pass/fail domain rules (text_property), averaging scores across rubrics. Open-ended responses that must obey strict compliance disclosures, tone, or structure without a fixed reference string.
rubric_based_tool_use_quality_v1 (ADK criterion key) RubricBasedCriterion(threshold=1.0, judge_model_options=..., rubrics=[Rubric(rubric_id="...", rubric_content=RubricContent(text_property="..."))]) Uses an LLM autorater to grade intermediate tool selection and parameter quality against natural-language rules. Dynamic tool calls (e.g., generated SQL or search queries) where exact string matching in tool_trajectory_avg_score is too brittle.
tool_trajectory_avg_score (ADK criterion key) ToolTrajectoryCriterion(threshold=1.0, match_type=MatchType.EXACT | MatchType.IN_ORDER | MatchType.ANY_ORDER) Deterministically compares actual intermediate_data.tool_uses (tool name + args) against the golden EvalCase. Verifying deterministic tool sequences (EXACT), prerequisite order (IN_ORDER), or concurrent parallel calls (ANY_ORDER).
final_response_match_v2 vs. response_match_score LlmAsAJudgeCriterion(threshold=0.8) vs. Float threshold (0.8) final_response_match_v2 uses an LLM judge for semantic equivalence against final_response; response_match_score computes lexical ROUGE-1 overlap. Upgrade from response_match_score to final_response_match_v2 when valid answers fail due to synonyms or paraphrasing!
hallucinations_v1 & safety_v1 (ADK criterion keys) LlmAsAJudgeCriterion(threshold=1.0, evaluate_intermediate_nl_responses=True) hallucinations_v1 verifies that every factual claim in the response is strictly supported by retrieved context/tool outputs. Preventing ungrounded fabrications in financial, medical, or legal RAG agents.
PointwiseMetric & PointwiseMetricPromptTemplate (Platform Eval SDK) PointwiseMetric(metric="custom_name", metric_prompt_template=PointwiseMetricPromptTemplate(criteria={"rule1": "..."}, rating_rubric={"1": "Pass", "0": "Fail"}, input_variables=[...])) Evaluates a single model/agent output per dataset row against custom criteria and rating_rubric definitions. Custom single-agent rubric scoring inside EvalTask(dataset=df, metrics=[...]).evaluate().
RubricBasedMetric (Platform Eval SDK) RubricBasedMetric(generation_config=RubricGenerationConfig(prompt_template=...), critique_metric=PointwiseMetric(...)) Dynamically generates prompt-specific pass/fail rubrics per test case (or uses predefined rubrics) and critiques the response against each rubric item. Evaluating diverse datasets where each prompt requires its own dynamically tailored checklist of rubrics!
PairwiseMetric & PairwiseMetricPromptTemplate (Platform Eval SDK) PairwiseMetric(metric="v1_vs_v2", baseline_model=baseline_fn, metric_prompt_template=PairwiseMetricPromptTemplate(criteria={...}, rating_rubric={...})) Runs side-by-side (A/B) LLM autorater judging between baseline_model and the candidate model, outputting win/loss/tie rates. Choosing whether Candidate Agent v2 outperforms Baseline Agent v1 before promoting v2 to production!

4. Master “if you see X, pick Y” decision matrix (Section 4)

Architectural requirement or scenario Recommended Google Cloud solution Anti-pattern to avoid
Fix intermittent trajectory test failures on a ParallelAgent Set match_type="ANY_ORDER" inside ToolTrajectoryCriterion (tool_trajectory_avg_score). Keeping match_type="EXACT" or removing trajectory evaluation.
Allow optional diagnostic helper tools between mandatory compliance tools Set match_type="IN_ORDER" inside ToolTrajectoryCriterion. Using ANY_ORDER (which ignores prerequisite order) or EXACT (which fails on helper tools).
Grade whether an agent’s reply includes mandatory legal disclaimers without a reference text Configure rubric_based_final_response_quality_v1 (RubricBasedCriterion with RubricContent) or PointwiseMetric. response_match_score (ROUGE-1 requires a fixed reference string and only counts word overlap).
Execute untrusted user-submitted code or binaries with strict kernel isolation GKE with Agent Sandbox (gVisor / microVM kernel isolation + warm sandbox pools). Standard shared-kernel containers or unisolated local execution.
Fix lost conversation history when Cloud Run scales past 1 container instance Configure an external persistent SessionService (VertexAiSessionService or DatabaseSessionService). Leaving InMemorySessionService active or relying only on load-balancer sticky cookies.
Test a new agent version on live production traffic with zero user impact Shadow / dark launch mode with all mutating/write tools mocked or disabled. Running shadow mode against live production write APIs (causes duplicate transactions!).

Golden rules for Section 4

  1. Evaluation: Combine trajectory evaluation (EXACT, IN_ORDER, ANY_ORDER) with rubric and groundedness autoraters (RubricBasedCriterion, hallucinations_v1, PointwiseMetric, PairwiseMetric).
  2. Runtimes & rollouts: Use Agent Runtime for turnkey AdkApp, Cloud Run (+ external SessionService) for scale-to-zero containers, GKE Agent Sandbox for untrusted code, session-pinned canary for stateful rollouts, and mocked write tools in shadow mode.
  3. Observability: Trace hops in Cloud Trace (W3C traceparent), stream logs to BigQuery for async autorater sampling and golden dataset harvesting, and reserve capacity via Provisioned Throughput!
