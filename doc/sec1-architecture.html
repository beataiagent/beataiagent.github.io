1.1 Architecture trade-offs, Workflow Builder, and prompt reasoning

⚠ The Rosku Bank over-engineering trap: using a multi-agent hammer for every nail!

Rosku Bank’s new AI task force wants to build a 5-agent LLM system for every project in the bank:

  1. CSV → BigQuery Fixed data pipeline: For a nightly CSV-to-BigQuery ledger job with fixed columns and a sub-50ms SLA, their LLM agent racks up $4,000/day in token fees and hallucinates rounding numbers!
  2. 💳 3 read-only APIs Simple FAQ bot: For a credit-card balance bot that only calls 3 read-only APIs, they build a 6-agent hierarchy that adds 9 seconds of slow handoff delay!
  3. 🧰 35 tools → 1 agent Overloaded monolith: Meanwhile, for a commercial loan system needing 35 distinct tools across legal, tax, and fraud departments, they cram all 35 tools into a single agent—confusing the LLM so it picks the wrong tools!
Module 1.1 in a nutshell
  • Don’t use AI for fixed math or pipelines: If inputs are structured (JSON/CSV) and rules are 100% known in advance, use Cloud Workflows or Dataflow ($0 LLM token cost and millisecond speed).
  • Need no-code task automation? Business users automating routine multi-app tasks (like summarizing an email and creating a Jira ticket) should use Gemini Enterprise Workflow Builder.
  • Single agent before multi-agent: Use 1 single agent (enhanced with CoT and few-shot templates) when working in 1 domain with under 10 tools. Upgrade to a multi-agent system only when you hit 15+ tools, conflicting personas, parallel speedups, or separate security identities (PAB).

1. Key definitions: what each tier is and why you need it

1. Deterministic cloud automation
Cloud Workflows & Dataflow
  • What it is: Code or YAML pipelines that run fixed API steps or high-volume data streams without an AI model.
  • Why you need it: Delivers 100% predictable branching, sub-second speed, and $0 LLM token cost whenever inputs are structured and rules are fixed.
now
2. Gemini Enterprise Workflow Builder
No-code business automation
  • What it is: A visual, no-code automation builder inside Gemini Enterprise for business users.
  • Why you need it: Lets non-developers chain event triggers, Gemini summarization steps, SaaS connectors (Jira, ServiceNow, Gmail), and human approval gates in minutes.
3. Single-agent system
1 domain + under 10 tools
  • What it is: One LLM agent handling open-ended natural-language requests inside one cohesive topic area.
  • Why you need it: When you have under 10 clear tools and one security identity, a single agent gives the fastest response time and lowest token cost.
1→3Ex
4. Chain-of-Thought and few-shot templates
CoT + 3 to 5 examples
  • What it is: Prompt instructions that tell a single agent to reason step-by-step (CoT) paired with 3–5 ideal input/output examples (few-shot).
  • Why you need it: Fixes reasoning mistakes and tool-ordering errors inside a single agent without adding multi-agent complexity.
5. Multi-agent system
Coordinator + specialist sub-agents
  • What it is: A team of specialized agents that divide and conquer complex work.
  • Why you need it: Essential when you hit tool overload (15+ tools), conflicting personas (Drafter vs. Critic), parallel fan-out speedups, or separate IAM/PAB security boundaries.

4. Real-world deep dive: hybrid pipelines, context pollution, CoT, and model tiering

Architect questionPlain-English answer
+
“What if a 10-step back-office mortgage pipeline has 9 fixed database steps, and ONLY Step 4 requires extracting unstructured notes from a scanned employer letter?”
  • Embed Gemini inside deterministic Cloud Workflows: Do not turn all 10 steps into an autonomous multi-agent chat!
  • Orchestrate the 10-step pipeline deterministically in Cloud Workflows, and have Step 4 make a single focused call to Gemini with a strict JSON schema before resuming Step 5 deterministically.
5 tools
“Our single agent only has 5 tools, but it occasionally skips a policy rule before calling a tool. Should we split it into 3 agents?”
  • No—apply Chain-of-Thought (CoT) and few-shot prompting first!
  • With only 5 tools in a single domain, adding multi-agent handoffs wastes latency and tokens. Adding a structured CoT reasoning template and 3–5 few-shot examples fixes single-domain reasoning without extra agents.
“Why does a single agent degrade when asked to inspect 150,000 tokens of raw Kubernetes, VPC, and database logs before answering?”
  • Context window pollution: Loading three massive raw log streams into a single agent’s conversation history bloats every subsequent reasoning turn.
  • Delegating each log stream to a specialized sub-agent isolates the raw logs inside the sub-agent’s scoped invocation and returns only a concise 10-line summary to the coordinator!
Flash 80%Pro 20%
“How does a multi-agent system keep costs low when 80% of user turns are simple greetings or routing lookups?”
  • Per-agent model tiering: Run the front-door Coordinator/Router agent on Gemini Flash (ultra-low latency and cost), and invoke Gemini Pro strictly inside the specialist sub-agent for the 20% of turns that need deep reasoning.
★ Golden rules for Module 1.1

Always apply Occam’s Razor for agents:

  1. Tier 1–2 If no natural-language reasoning is needed → select deterministic automation (Cloud Workflows / Dataflow) or Gemini Enterprise Workflow Builder (for no-code multi-app tasks).
  2. Tier 3 If 1 cohesive persona with under 10 tools can solve it → select a single agent (optimized with Chain-of-Thought and few-shot templates).
  3. Tier 4 Only pay the orchestration cost of a multi-agent system when you hit tool overload (15+ tools), conflicting personas, parallel fan-out needs, or IAM/PAB isolation boundaries!
