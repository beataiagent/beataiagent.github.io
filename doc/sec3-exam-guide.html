3.0 Domain 3 roadmap: Developing custom agents (33% weight)

Domain 3 in a nutshell (~33% exam weight)
  • Single-agent parameters and multi-agent workflows (3.1 & 3.2): Configure ADK LlmAgent routing (description vs. instruction), 2-step tools + output_schema splits, include_contents=‘none’, and orchestrate SequentialAgent, ParallelAgent (unique output_keys), LoopAgent (escalate=True), AgentTool, and CustomAgent (BaseAgent).
  • Tools, grounding, and state/memory (3.3, 3.4 & 3.5): Connect databases via MCP Toolbox (tools.yaml), choose between Agent Search (ACLs), RAG Engine, and Context Caching, and scope state across temp:, session, user:, app:, Memory Bank, and GcsArtifactService.
  • Cross-service interoperability (3.6): Connect distributed multi-team and cross-cloud agents via the Agent2Agent (A2A) protocol (/.well-known/agent.json, SSE streaming, push webhooks, and input-required resumption).

Core architectural topics in Domain 3 (~33%)

1. Single-agent ADK parameters and prompting (Module 3.1)
  • Master description (parent routing) vs. instruction (internal behavior and {state_key} interpolation), output_schema vs. output_key state handoffs, include_contents=‘none’ history pruning, planners (BuiltInPlanner, PlanReActPlanner), and Gemini Flash vs. Pro tiering.
2. Multi-agent workflow and routing patterns (Module 3.2)
  • Design deterministic pipelines with SequentialAgent, ParallelAgent (unique output_key isolation), LoopAgent (terminated via EventActions(escalate=True) or max_iterations), imperative CustomAgent (BaseAgent), and dynamic LlmAgent(sub_agents=[…]) vs. AgentTool routing.
3. MCP Toolbox for Databases and custom tools (Module 3.3)
  • Configure declarative tools.yaml (sources, tools, toolsets) for pooled, parameterized database access, write typed Python FunctionTools with ToolContext, and integrate OpenAPIToolset and LongRunningFunctionTool.
4. Agent Search, RAG Engine, and Context Caching (Module 3.4)
  • Choose between turnkey Agent Search (with native connectors and query-time document ACLs), custom Vertex AI RAG Engine (custom chunking, embeddings, and semantic reranking), and Gemini Context Caching for large static prompt prefixes.
5. State prefixes, Memory Bank, and ArtifactService (Module 3.5)
  • Scope state variables with temp:, unprefixed session, user:, and app: prefixes, extract long-term cross-session facts in Memory Bank, and version large binary files in GcsArtifactService.
6. Agent2Agent (A2A) interoperability (Module 3.6)
  • Publish and consume A2A Agent Cards (/.well-known/agent.json via to_a2a and RemoteA2aAgent), stream live updates via SSE, handle multi-hour jobs via push notification webhooks, and resume input-required tasks using contextId and taskId.
