Why a
Decisions API?

Purpose-built primitives
for bounded choices

ช่วงที่ 1 • เริ่มจากปัญหา: ทำไมการใช้ LLM แบบ generate text มาตอบคำถามปิดถึงไม่คุ้ม
The problem

Many AI calls are really closed-set decisions

Tool selection · policy checks · model routing · context grading

Generative model
  • Writes the answer token by token
  • Pay for output & thinking tokens
  • Parse free text back into a label
  • No calibrated sense of "how sure"
Gemini Decision 1
  • Scores candidate options in one forward pass
  • Returns probabilities, not prose
  • Confidence score from 0 to 1
  • $0 for output tokens
ในแอป AI จริง ๆ หลาย call เป็นคำถามปิด: จะเรียก tool ไหน, ผิด policy ไหม, ส่งไปโมเดลไหน, context นี้เกี่ยวข้องไหม • ถ้าใช้โมเดล generative ต้องรอมันเขียนทีละ token, จ่ายค่า output/thinking, แล้ว parse ข้อความกลับเป็น label และไม่รู้ว่ามั่นใจแค่ไหน • Gemini Decision 1 ให้คะแนนทุกตัวเลือกใน forward pass เดียว คืนค่าเป็นความน่าจะเป็นพร้อม confidence 0–1

ส่ง input ก้อนเดียว (มัลติโมดัลได้) พร้อมคำถามอิสระได้ถึง 1,000 ข้อ • โมเดลไม่ได้ generate ข้อความ แต่ให้คะแนนตัวเลือกทั้งหมดใน forward pass เดียว • ได้ความน่าจะเป็นและ confidence กลับมา • จุดที่ทรงพลัง: เอา confidence มาเขียน logic ได้เลย เคสชัดก็ทำต่ออัตโนมัติ เคสกำกวมส่งไปโมเดลที่ใหญ่กว่าหรือให้คนตรวจ
Question types · mix them in one request

Three question types

"noul"

Yes / No

Probability that a condition holds. Optional true / false description criteria.
"choice"

Multiple choice

Pick from 2 to 255 choices. Returns the winner + normalized probabilities for every candidate.
"score"

Ordered rubric

Grade against an ordered rubric (starting at 0). Returns a continuous weighted score + per-level probabilities.
คำถามมี 3 แบบ: (1) noul = ใช่/ไม่ใช่ ได้ความน่าจะเป็นว่าเงื่อนไขเป็นจริง ใส่ criteria ของ true/false เพิ่มได้ (2) choice = เลือก 1 จาก 2–255 ตัวเลือก ได้ตัวที่ชนะพร้อม probability ของทุกตัวเลือก (3) score = ให้คะแนนตาม rubric ที่เรียงลำดับ เริ่มจาก 0 ได้คะแนนต่อเนื่องแบบถ่วงน้ำหนักและ probability ของแต่ละระดับ • ทั้ง 3 แบบผสมกันใน request เดียวได้
Input

Natively multimodal

TextImagesAudioVideoPDFs

Combine modalities

A call recording + account metadata, or a scanned PDF claim + damage photos — in one input.

Tunable resolution

Set image & video resolution to trade visual detail against token cost.

No extra pipelines

No separate audio transcription or OCR step — and no separate bill for them.
สร้างบนสถาปัตยกรรมมัลติโมดัลของ Gemini: ส่งข้อความ รูป เสียง วิดีโอ PDF ได้ตรง ๆ • ผสมกันได้ เช่น ไฟล์เสียง call center + ข้อมูลบัญชีลูกค้า หรือ PDF เคลมประกัน + รูปความเสียหาย • ปรับ resolution ของรูป/วิดีโอเพื่อคุมคุณภาพกับค่า token • ไม่ต้องทำ OCR หรือถอดเสียงแยก และไม่มีค่าใช้จ่ายส่วนนั้นเพิ่ม

Code · Python · 1/2 · google-genai SDK

Example: breakroom spill check


from google import genai

client = genai.Client(http_options={"api_version": "v1beta"})

result = client.decisions.create(
    model="gemini-decision-1",
    input=[
        {"type": "image", "mime_type": "image/jpeg",
         "uri": "https://storage.googleapis.com/generativeai-downloads/images/gemini-decisions-slides/spill.jpg"},
        {"type": "text",
         "text": "Breakroom counter check before the 9 AM client meeting."},
    ],
    questions={
        "has_spill": {
            "type": "noul",
            "instructions": "Is there an uncleaned liquid spill on the counter?",
        },
        "next_action": { ... },   # next slide
        "severity":    { ... },   # next slide
    },
)
pip install google-genai
  • client.decisions.create with gemini-decision-1
  • input uses the same Content blocks as the Interactions API
  • Image + text context in one input
ตัวอย่างจากบล็อก ส่วนที่ 1: สร้าง client ด้วย api_version v1beta แล้วเรียก client.decisions.create กับโมเดล gemini-decision-1 • input เป็นรูปเคาน์เตอร์ห้องพักพนักงาน + ข้อความบริบท ใช้ format Content แบบเดียวกับ Interactions API • คำถามแรก has_spill แบบ noul (ใช่/ไม่ใช่) ว่ามีน้ำหกที่ยังไม่เช็ดไหม
Code · Python · 2/2

Choice & rubric questions


"next_action": {
    "type": "choice",
    "instructions": "Which cleanup action fits the scene?",
    "criteria": {
        "wipe_with_cloth":
            "Small counter spill with a cloth or towel already nearby.",
        "dispatch_janitorial":
            "Large floor hazard, broken glass, or active leak.",
        "ready_for_meeting": "Counter is clean and ready.",
    },
},
"severity": {
    "type": "score",
    "instructions": "Rate the severity of the counter mess.",
    "criteria": [
        "Clean and ready.",              # level 0
        "Minor localized spill.",        # level 1
        "Major spill or safety hazard.", # level 2
    ],
},
  • choice: criteria is a dict — label → description
  • score: criteria is an ordered list, starting at level 0
  • Named questions → named answers
Result in the blog: spill detected, next_action = wipe_with_cloth
ส่วนที่ 2 (อยู่ใน questions เดียวกัน): next_action แบบ choice มี 3 ตัวเลือกพร้อมคำอธิบายว่าเมื่อไหร่ควรเลือก • severity แบบ score ใช้ rubric เรียงลำดับ 0 = สะอาด, 1 = หกเล็กน้อย, 2 = หกมาก/อันตราย • ผลในบล็อก: ตรวจเจอน้ำหก และแนะนำ wipe_with_cloth
Docs · response shape

What comes back

noul · Yes/No


{"type": "noul",
 "noul": 0.99,
 "confidence": 0.99}

P(yes), clamped 0.01–0.99
confidence = max(p, 1 − p)

choice


{"type": "choice",
 "choice": "billing",
 "probabilities": {
   "billing": 0.99,
   "shipping": 0.004, ...},
 "confidence": 0.99}

Probabilities sum to 1
confidence = top option

score · rubric


{"type": "score",
 "score": 1.12,
 "legend": {"0": "...", ...},
 "probabilities": {
   "0": 0.03, "1": 0.83, "2": 0.15},
 "confidence": 0.83}

Weighted average of levels —
can fall between levels

Top level: answers (same keys you sent) + usage — total_output_tokens: 0

รูปแบบผลลัพธ์จาก docs: ได้ answers ที่ key ตรงกับคำถามที่ส่งไป + usage • noul = ความน่าจะเป็นว่า 'ใช่' อยู่ระหว่าง 0.01–0.99 และ confidence = max(p, 1−p) • choice = ตัวที่ชนะ + probabilities ของทุกตัวเลือกรวมกันได้ 1, confidence = ค่าของตัวที่ชนะ • score = ค่าเฉลี่ยถ่วงน้ำหนักของ level จึงออกมาเป็น 1.12 ได้ มี legend และ probabilities ต่อ level • usage แสดง output tokens เป็น 0 เสมอ (ตัวเลขในตัวอย่างมาจากตัวอย่างใน docs คนละเคสกัน)
Docs · Python

Act on confidence


a = result.answers

spill = a["has_spill"]
if spill.noul > 0.9 and spill.confidence > 0.6:
    action = a["next_action"].choice
    # → wipe_with_cloth / dispatch_janitorial / ...

sev = a["severity"]
level = max(sev.probabilities, key=sev.probabilities.get)
print(sev.score, sev.legend[level])

if a["next_action"].confidence < 0.7:
    send_to_human_review()   # or a bigger model
Tune thresholds on labeled examples from your own traffic — weigh false positives vs. false negatives.
noul tops out at 0.99 — a check like > 0.99 never matches.

Thresholds shown are illustrations from the docs, not recommended values.

เอา confidence มาใช้ในโค้ด: (1) ถ้า has_spill มั่นใจว่าใช่ ค่อยอ่าน next_action ไปทำงานต่อ (2) score ถ้าอยากได้ level เป็นจำนวนเต็มให้เลือก level ที่ probability สูงสุด แล้วดูคำอธิบายจาก legend (3) ถ้า confidence ต่ำ ส่งให้คนตรวจหรือโมเดลใหญ่ • docs ย้ำว่า threshold ต้องตั้งจากข้อมูลจริงที่ label แล้ว ตัวเลข 0.9/0.6/0.7 เป็นแค่ตัวอย่าง • ระวัง noul สูงสุดแค่ 0.99 เช็ค > 0.99 จะไม่มีวันจริง • send_to_human_review เป็นฟังก์ชันสมมติของเราเอง

Docs · best practices

Writing good questions

One decision each

Split independent checks into separate questions in the same request.

Full question in instructions

The model never sees the question key.

Describe every option

Short descriptions for choices & rubric levels. Keep score scales linear.

Plan for "none fit"

Choice always spreads probability. Check confidence, add a scope check or an "other" key.

Ask positively

Avoid negated questions — subtract in code. Compare numbers & dates in code too.

Input is untrusted

Explicit criteria, test adversarial inputs, keep a human on high-stakes actions.
tips จาก docs: (1) หนึ่งคำถามหนึ่งการตัดสินใจ ถ้ามีหลายเรื่องให้แยกเป็นหลายคำถามใน request เดียว (2) โมเดลไม่เห็น key ของคำถาม ต้องเขียนคำถามเต็มใน instructions (3) ใส่คำอธิบายสั้น ๆ ทุกตัวเลือกและทุก level, scale ของ score ต้องเป็นเชิงเส้นเพราะคิดค่าเฉลี่ยจาก index (4) choice จะกระจาย probability เสมอแม้ไม่มีตัวไหนตรง ให้เช็ค confidence หรือเพิ่ม key 'other' (docs บอกให้เลี่ยง none_of_the_above) (5) ถามเชิงบวก แล้วกลับค่าในโค้ด ส่วนการเทียบตัวเลข/วันที่ให้ทำในโค้ด (6) input ถือว่าไม่น่าไว้ใจ ทดสอบ prompt injection และให้คนตรวจงานเสี่ยงสูง

Limits & rate limits

  • 262,144 tokens context — shared by input + all questions
  • 1–1,000 questions · 2–255 choices · 2–255 rubric levels (2–10 recommended)
  • Inline base64 up to 100 MB (PDF 50 MB) · public/signed URLs up to 15 MB
  • No YouTube URLs or gs:// · text-only instructions
  • Resolution: low · medium · high · ultra_high (images only)
